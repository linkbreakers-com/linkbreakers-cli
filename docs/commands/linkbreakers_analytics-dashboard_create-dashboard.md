## linkbreakers analytics-dashboard create-dashboard

Create analytics dashboard

### Synopsis

Requires the `analytics:write` scope.

API: POST /v1/analytics/dashboards

```
linkbreakers analytics-dashboard create-dashboard [flags]
```

### Options

```
      --config string            Initial widgets. Empty means the dashboard starts with none, because its contents are normally agreed with the assistant before anything is created. JSON value.
      --data string              Request body as JSON. Use @file.json to read a file or - for stdin. Flags set fields on top of it.
  -h, --help                     help for create-dashboard
      --id string                Client-supplied dashboard id. Generated server-side when empty.
      --idempotency-key string   Makes retrying this request safe. See components.parameters.IdempotencyKey.
      --link-id string           Link to scope this dashboard to. Empty creates the workspace-wide dashboard.
      --name string              Display name. Defaults to "Default Dashboard" when empty.
      --use-default-widgets      Fill the dashboard with a starter set instead of leaving it empty, for a dashboard made in one step rather than agreed in a conversation. Without link_id it is the workspace set (scans over time, top links, geography, technology and more). With link_id it is the link set: scans over time, geography, technology, peak hours, and new versus returning visitors, which is everything any link records. The service applies it to any link; whether it suits one is the caller's judgement, since a workflow that collects answers deserves widgets for them. Ignored when config is set, and hidden from the assistant, which agrees its widgets with the user and would otherwise stack them on top of these.
```
