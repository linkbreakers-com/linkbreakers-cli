## linkbreakers analytics-dashboards create

Create analytics dashboard

### Synopsis

Create a dashboard with its widgets, for the whole workspace or scoped to one link.

Requires the `analytics:write` scope.

API: POST /v1/analytics/dashboards

```
linkbreakers analytics-dashboards create [flags]
```

### Options

```
      --config string            Initial widgets. Empty means the dashboard starts with none, because its contents are normally agreed with the assistant before anything is created. JSON value.
      --data string              Request body as JSON. Use @file.json to read a file or - for stdin. Flags set fields on top of it.
  -h, --help                     help for create
      --id string                Client-supplied dashboard id. Generated server-side when empty.
      --idempotency-key string   A unique value per request, such as a UUID, that makes retrying it safe: a retry with the same key and body returns the first response instead of acting twice.
      --link-id string           Link to scope this dashboard to. Empty creates the workspace-wide dashboard.
      --name string              Display name. Defaults to "Default Dashboard" when empty.
      --use-default-widgets      Fill the dashboard with a starter set instead of leaving it empty, for a dashboard made in one step rather than agreed in a conversation. Both sets open on three big numbers with their trend: visits, new visitors and returning visitors. Without linkId it is the workspace set (scans over time, top links, geography, technology and more). With linkId it is the link set: scans over time, geography, technology, peak hours, and new versus returning visitors, which is everything any link records. The service applies it to any link; whether it suits one is the caller's judgement, since a workflow that collects answers deserves widgets for them. Ignored when config is set, and hidden from the assistant, which agrees its widgets with the user and would otherwise stack them on top of these.
```
